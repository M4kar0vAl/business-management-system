# Система управления бизнесом

## Функционал
Система предоставляет два способа взаимодействия:
- **API**
- **Веб-интерфейс**

### API

1. **Регистрация и аутентификация пользователей**
   - Регистрация по email и паролю
   - Два способа аутентификации:
     - bearer токен (для апи взаимодействия)
     - cookie (для веб-интерфейса)
2. **Профиль пользователя**
   - Получение информации
   - Обновление
3. **Управление пользователями** (для админов)
   - Список пользователей
   - Получение информации по конкретному пользователю
   - Изменение пользователя (включая смену ролей)
   - Удаление пользователя
4. **Управление командами и пользователями в командах**
   - Создание команды
   - Получение списка команд
   - Получение информации по команде
   - Получение списка участников команды
   - Добавление и удаление участников
   - Смена ролей (можно назначить только обычным пользователем или менеджером; админом не назначить)
   - Получение списка задач команды 
5. **Управление задачами**
   - Создание задачи
   - Получение информации по задаче
   - Обновление задачи
   - Удаление задачи
   - Назначить исполнителя задачи
   - Обновить статус (только исполнитель)
   - Получение списка назначенных задач
   - Получение списка созданных задач (для менеджеров и админов)
   - Получение списка задач за период (для календаря)
6. **Комментарии к задачам**
   - Создание комментария
   - Получение списка комментариев для задачи
   - Обновление комментария (только автор)
   - Удаление комментария (только автор)
7. **Оценки задач**
   - Создание оценки задачи
   - Изменение оценки (только автор)
   - Удаление оценки (только автор)
   - Получение оценки текущего пользователя для задачи
   - Получение списка оценок всех задач, назначенных на пользователя
   - Получение средней оценки всех задач, назначенных на пользователя
8. **Встречи**
   - Создание встречи
   - Получение списка встреч
   - Получение информации о встрече
   - Отмена встречи (удаление)
   - Добавление и удаление участников
   - Получение списка встреч пользователя
   - Получение списка встреч за период (для календаря)

#### Документация

После [установки и запуска](#установка-и-запуск) проекта документация API будет доступна по
адресу [http://localhost/docs](http://localhost/docs) 

### Веб-интерфейс

#### Страницы

- **Главная (`/`)**
- **Регистрация (`/auth/register`)** - для не аутентифицированных
  - Форма регистрации (email и пароль)
- **Логин (`/auth/login`)** - для не аутентифицированных
  - Форма для входа (email и пароль)
- **Профиль (`/users/me`)** - для аутентифицированных
  - Отображение информации о пользователе
  - Форма для изменения
- **Список пользователей (`/users/`)** - для админов
  - Список с информацией по каждому пользователю
  - Кнопка для удаления пользователя
- **Список команд (`/teams/`)** - для аутентифицированных
  - Ссылка на страницу создания команды (для админов)
  - Список с информацией по всем командам
  - Ссылки на страницы деталей команд (для участников команды)
- **Создание команды (`/teams/create`)** - для админов
  - Форма для создания команды (название, описание)
- **Детали команды (`/teams/{team_id}`)** - для участников
  - Информация по команде
  - Список участников
    - Ссылка на страницу добавления участника (для админа)
    - Информация по каждому участнику
    - Форма для изменения роли (для админа)
    - Кнопка удаления из команды (для админа)
  - Список задач команды
    - Ссылка на страницу создания задачи (для менеджера или админа)
    - Календарь с отображением всех задач команды (задачи кликабельны и ведут на детали задачи)
    - Информация по каждой задаче
    - Форма обновления статуса задачи (для назначенного пользователя)
    - Форма для назначения исполнителя (для менеджера и админа; для не назначенных задач)
    - Ссылки на детали задач
    - Кнопка удаления задачи (для менеджера и админа)
- **Добавление участника в команду (`/teams/{team_id}/add_member`)** - для админа
  - Форма для добавления (email пользователя)
- **Создание задачи (`/tasks/teams/{team_id}/create_task`)** - для менеджера или админа
  - Форма для создания задачи (описание и дедлайн)
- **Детали задачи (`/tasks/{task_id}`)** - для участников
  - Информация по задаче
  - Форма обновления статуса задачи (для назначенного пользователя)
  - Форма для назначения исполнителя (для менеджера или админа; для не назначенных задач)
  - Ссылка на страницу изменения задачи (для менеджера или админа, являющегося автором задачи)
  - Кнопка удаления задачи (для менеджера или админа, являющегося автором задачи)
  - Оценка задачи текущим пользователем (для менеджера и админа)
    - Форма для создания оценки (задача должна быть выполнена)
    - Форма для изменения оценки (задача должна быть выполнена)
    - Кнопка для удаления оценки
  - Оценки задачи (для назначенного пользователя)
    - Средняя оценка за задачи
    - Список оценок
  - Комментарии
    - Форма для создания комментария
    - Список комментариев
      - Форма изменения комментария (для автора)
      - Кнопка удаления комментария (для автора)
- **Изменение задачи (`/tasks/{task_id}/edit`)** - для менеджера или админа, являющегося автором задачи
  - Форма для изменения задачи (описание, дедлайн, статус)
- **Список оценок задач текущего пользователя (`/tasks/my_evaluations/`)** - для аутентифицированных
  - Форма для фильтрации оценок (дата начала, дата конца, задача)
  - Средняя оценка по задачам
  - Список оценок
    - Ссылка на страницы деталей задач (для участника команды задачи)
- **Список встреч (`/meetings/`)** - для аутентифицированных
  - Ссылка на страницу создания встречи (для менеджера или админа)
  - Календарь с отображением всех встреч (встречи кликабельны и ведут на страницы деталей)
  - Форма для фильтрации встреч (дата начала, дата конца)
  - Список встреч
    - Ссылки на страницы деталей встреч
    - Кнопка удаления (для автора)
- **Создание встречи (`/meetings/create`)** - для менеджера или админа
  - Форма для создания встречи (дата-время начала и дата-время конца)
- **Детали встречи (`/meetings/{meeting_id}`)** - для аутентифицированных
  - Информация по встрече
  - Кнопка удаления (для автора)
  - Участники
    - Форма добавления участника (email)
    - Список участников
    - Кнопка удаления участника (для менеджера или админа)
- **Список встреч текущего пользователя (`/meetings/my`)** - для аутентифицированных
  - Календарь с отображением всех встреч пользователя
  - Форма для фильтрации встреч (дата начала, дата конца)
  - Список встреч
    - Информация по встрече
    - Кнопка удаления (для автора)

На всех страницах присутствуют:
- Навигация по страницам
- Ссылки на страницы регистрации/логина (для не аутентифицированных)
- Кнопка логаута и ссылка на страницу профиля (для аутентифицированных)

## Установка и запуск

### Установка

1. Клонировать репозиторий
    ```shell
    git clone https://github.com/M4kar0vAl/business-management-system.git
    ```

2. В корне проекта создать файл `.env` и наполнить по аналогии с `.env.example`

### Запуск

#### Make

```shell
make run
```

#### Docker compose

```shell
docker compose up -d --build
```

### Остановка

#### Make

```shell
make down
```

#### Docker compose

```shell
docker compose down
```

## Создание суперпользователя

1. В `.env` файле указать две переменные:
   - `BMS__USER__ADMIN_EMAIL` - email суперпользователя
   - `BMS__USER__ADMIN_PASSWORD` - пароль суперпользователя
2. Запустить приложение. Суперпользователь будет создан автоматически

**Дефолтные значения указаны в `app.config.users.UserConfig`**

## Структура проекта

Структура проекта вдохновлена репозиторием [fastapi-best-practices](https://github.com/zhanymkanov/fastapi-best-practices?tab=readme-ov-file#project-structure).

В корне проекта лежат:
- `alembic/` - настройки alembic и миграции
- `app/` - основное приложение (точка входа здесь)
- `templates/` - шаблоны для веб-интерфейса
- `tests/` - тесты

В `app/` создается папка приложения (домена), в которой располагаются модули относящиеся к этому домену.

Из основных модулей:
- `schemas.py` - pydantic схемы
- `models.py` - модели БД
- `routers.py` - роутеры
- `admin.py` - классы для админки
- `repositories.py` - репозитории (БД логика)
- `services.py` - сервисы (вызывают методы репозиториев, проверяют права, бросают исключения бизнес логики)
- `dependencies.py` - FastAPI зависимости
- `exceptions.py` - кастомные исключения для этого приложения
- `exception_handlers.py` - обработчики исключений из exceptions.py. Маппят python исключения к http статусам ответов

Если модуль разрастается или если можно сразу выделить несколько сущностей, то модуль меняется на пакет,
в котором через `__all__` экспортируются нужные сущности. Таким образом, импортироваться они будут так, будто лежат в модуле.

Если какая-то сущность нужна в нескольких приложениях, то она выносится на уровень всего приложения в `app/`,
где создается модуль или пакет с необходимыми сущностями.
